Rate-limit the public search endpoint

Search is the only unauthenticated path that reaches Redis. A single client can exhaust the connection pool for everyone. This puts a fixed-window limiter in front of it.

Goal · what done means

  • Verified — 100 requests in 60s from one IP returns 429 after the 60th. pnpm vitest run mw/rate-limit
  • Verified — authenticated traffic is unaffected. pnpm playwright test search
  • Verified — Redis pool utilisation stays below 60% at 500 rps. make loadtest:search
  • Human judgement — the 429 body is actionable for API consumers.

3 of 4 machine-checkable. The fourth is marked, not hidden — it is the only part of the status score a model may speak to.

Risks & unknowns

  • A fixed window permits a 2× burst at the boundary. Accepted for v1; sliding window is a follow-up, recorded as an addendum on this item.
  • Redis becomes a hard dependency of the request path. The counter has no local fallback — if Redis is down, the limiter fails open, which is deliberate and tested.
  • Unresolved — no ADR covers limiter policy. docs/adr/ is registered in the knowledge contract but empty.
