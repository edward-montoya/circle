Circle AI · Observation app · Iteration 5 — design guidelines

One shell, eleven screens,
one navigation model

Iteration 3 drew ten separate pictures. This is one application: the sidebar is byte-identical on every screen, contextual navigation lives only in the tab row, and every screen is reachable from the flow below.

New in iteration 5 — tasks. They were missing entirely: the brief called them “units” and nothing listed them. S04 makes the task graph a first-class tab, and every task now carries a one-sentence goal, a verification kind and command, and the evidence that closed it. See circle-ai.flows.html for the contract and the cross-surface flows.

All screens show one world state — acme/platform, preflight passing, 5 items, 14 sessions, 2 briefs pending, task-118 in flight with drift and a phantom commit. The only exception is S10, which is labelled as a different moment in time.

Navigation model the rules every screen obeys

Three navigation levels — and nothing else

LevelWhere it livesContentsRule
1 · GlobalSidebar Overview · Items · Sessions ‖ Approvals · Activity · Quality · Contracts Identical on every screen. Same seven entries, same order, same badges. Only the active state moves. Never holds contextual items.
2 · ObjectTab row Fixed tab set per object type Appears only on a detail screen. An Item always shows the same six tabs; a Session always shows the same five. Never varies by state.
3 · WithinMaster–detail List on the left, reader on the right Selecting an artifact never navigates away. Global nav and tabs stay on screen — the fault in iteration 3.

Tab sets are fixed. Item: Brief · Tasks · Timeline · Quality · Sessions · Addenda. Session: Artifacts · Tasks · Timeline · Gate events · Claude sessions · Usage. A tab with nothing in it renders empty, never disappears — a nav that changes shape is a nav you cannot learn.

Tasks appear on both objects, deliberately. An item owns its task graph; a session shows the subset it worked on, with the Claude session that closed each one. Same records, two questions: what is left to do versus what did this session actually do.

Component vocabulary the only pieces any screen may use

Status chips — closed set

approved pass live mergedGreen · confirmed by an executed command or a recorded event
pending drift forcedAmber · needs a human, but nothing is broken
phantom gate red deadRed · a claim that failed verification
syncing eventBlue · informational, in progress
rewritten abandoned humanGrey · true but inert

Artifact provenance badges

BRWritten — produced by the session, committed with the repo
DOCRead — consulted from the knowledge registry. The traceability record
FIGGenerated — derived, regenerable, not authored
ADRMissing — registered but unresolved. Shown as a gap, never omitted

Actions — three kinds only

 Consequential · destructive · neutral. No action ever dispatches an agent.
