## Goal
`*.pdf` files in MAIL_DIR become Messages alongside `.eml` files, so the Digest, `/api/digest` and `/` include mail that arrived as PDF, each marked with its Source.

## Decisions
- Extends `daily-digest` (v1 app: `app/mailbox.py` parsing, Digest per UTC day, `/` and `/api/digest`); nothing it delivers is rebuilt. This item lands after it and adds a PDF reader beside the `.eml` reader inside the Mailbox loading seam — the Digest function is untouched, so counting, ranking, Threads, Action Items and Needs Reply behave exactly as before.
- `pypdf` (pure Python) reads PDFs; it is pinned in `requirements.txt` and installed with `pip install -r` at image build — one declared dependency, no system packages.
- The image build stays portable (docs/DEV-ENVIRONMENT.md): the Dockerfile takes `HTTPS_PROXY` and `PIP_CERT`-style settings as build args/env with empty defaults, compose passes them from the host environment, and the proxy CA is supplied by compose (build context or secret/mount from a variable) only when set. No proxy URL, CA path or `--network host` is written into a committed file. On a normal machine the unset variables make the build a plain `pip install`.
- A PDF Email is recognised by `From:`, `To:`, `Subject:`, `Date:` lines in the first page's text; the Header Block ends at the first blank line or first line that is not a header (continuation lines are folded into the previous header); the rest of the page and later pages' text form the body. Header names are matched case-insensitively. Only the first page is used to find headers.
- `From:` is reduced to the address like the `.eml` path (`Name <addr>` → `addr`); `Date:` accepts RFC 2822 form, as mail clients print it, and is converted to UTC; a missing zone is taken as UTC (same as `.eml`). Missing `Subject:` → empty subject, missing `To:` is fine (assumed).
- A PDF without a parseable From and Date, a PDF that cannot be opened, and an encrypted PDF are Skipped Files: counted, never raised. (assumed) The count covers PDFs only; `.eml` files without a date keep being skipped silently as in v1.
- (assumed) The Skipped File count is shown as `skipped` (integer, additive field) in the `/api/digest` JSON and as one quiet line on the HTML page only when it is above zero. It counts for the whole Mailbox, not per Digest Day, since a skipped file has no day.
- Each Message carries `source` (`eml` | `pdf`). JSON: each thread message entry gains `source`. (assumed) HTML: a small badge next to each message, text `PDF` shown for pdf and `EML` for eml, escaped like all text. The existing v1 JSON keys are unchanged; changes are additive only.
- Mailbox loading is the seam: `load_messages(directory)` keeps returning Messages from both file kinds, in a deterministic order (sorted by file name across both kinds); the Skipped File count comes from the same pass, so the web layer reads the Mailbox once per request as before.
- Samples are generated by a committed script (`scripts/make_sample_pdfs.py`) from fixed text, and the generated PDFs are committed in `samples/mail/` so the app needs no generator at run time. (assumed) The script and the PDF fixtures for tests use `reportlab`, listed in a separate `requirements-test.txt`, installed in the same image (the one image serves `web` and `test`; accepted for simplicity). Reproducibility: fixed document metadata/dates and `invariant=1` so rerunning gives identical bytes.
- Three sample PDF Emails on 10, 11 and 12 March 2025, one per day, using distinct new senders/subjects except one that is a reply (`Re:`) in an existing Thread (`Q1 budget review` or `Invoice 4471`). The daily-digest unit tests assert on the 10 `.eml` samples; this item must update any such expectations (counts per day) it breaks, and a test pins the new totals.
- Test PDFs for unit tests are real PDF files generated by the same helper, written into a temp directory by the test; a malformed PDF is a file with `.pdf` name and garbage bytes. No binary fixtures are hand-edited.
- Gates: unit tests in `tests/unit` (`test:unit`), HTTP test in `tests/integration` (`test:integration`), both through `docker compose run --rm test`. Both prove the container because the image build installs `pypdf` — an import failure there fails every test.
- Language: Source, PDF Email, Header Block, Skipped File are recorded in `app/DOMAIN.md`; daily-digest is editing the same file, so changes here are appended, nothing reorganised.

## Behaviours
- A `.pdf` file in MAIL_DIR whose first page has a Header Block with From and Date becomes a Message with sender address, UTC date, subject and body — proved by `test:unit` (real PDF in, Message out)
- Header lines are matched case-insensitively, wrapped header values are joined, and `Name <addr>` becomes the address — proved by `test:unit`
- Body is the text after the Header Block, including text on later pages — proved by `test:unit`
- A PDF with no parseable From or Date, a malformed PDF (garbage bytes) and an encrypted PDF are skipped and counted without raising, and the other files in the Mailbox still load — proved by `test:unit`
- `.eml` and `.pdf` files in one directory both load, in a deterministic order, and every Message has `source` `eml` or `pdf` accordingly — proved by `test:unit`
- A PDF Message of a Digest Day is counted, ranked as a Sender, grouped into Threads (including a PDF reply joining an `.eml` Thread, and the reverse), and its Action Items are found, exactly like an `.eml` Message — proved by `test:unit` (Digest over mixed Messages)
- `GET /api/digest?date=` includes the PDF Email in `senders`/`threads` with `"source": "pdf"` on its message, `.eml` messages have `"source": "eml"`, and `skipped` reports the Skipped File count — proved by `test:integration` (server in-process on a sample directory containing real PDFs, including one malformed)
- `GET /` shows a source badge per message and the skipped line only when the count is above zero, with PDF text escaped — proved by `test:integration` (badge text and escaping asserted in HTML); how it looks is manual (no browser gate declared)
- The shipped samples hold three PDF Emails on the same three days as the `.eml` samples, one a reply in an existing Thread, and the digest of each day with the samples in `samples/mail/` has the expected totals — proved by `test:unit`
- Running `scripts/make_sample_pdfs.py` again reproduces the committed sample PDFs byte for byte — proved by `test:unit` (generate to a temp directory, compare with `samples/mail/*.pdf`)
- The image installs `pypdf` from `requirements.txt` on a normal machine and behind the proxy of docs/DEV-ENVIRONMENT.md without machine-specific values in committed files — proved by `test:unit` (the suite imports `pypdf` inside the built image); the proxy path is manual (this machine's proxy is the only one that can be exercised; checked by building with `HTTPS_PROXY` and the CA supplied from the environment, and that a build with them unset has no hard-coded fallback — read the Dockerfile and compose for none)

## Out of scope
- OCR of scanned PDFs (a PDF with no extractable text has no Header Block and is a Skipped File)
- Attachments inside `.eml` files
- Encrypted PDFs (counted as Skipped Files, never decrypted)
- PDFs whose text layout puts headers in a table, in two columns, or in images
- Rendering the PDF itself in the page
- Reading headers from PDF document properties
- Time zone names that RFC 2822 does not carry (e.g. "PST" is the only form handled via the standard parser; others become Skipped Files)
- Any other third-party dependency beyond `pypdf` (runtime) and `reportlab` (sample/test generation)
- Changes to the Digest rules, ranking, Threads or Action Items
